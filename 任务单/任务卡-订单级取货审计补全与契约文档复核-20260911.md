## 第一部分 · 代码：补 `pickupOrder()` 审计

### 1.1 改动（唯一代码 diff，`courier.service.ts`）

`pickupOrder()`（`POST /courier/order/:orderId/pickup`）transaction 后新增 `this.audit.log({...})`：

- **action = `COURIER_PICKUP`**（沿用任务级同名）——同语义同名的理由：审计页按 action 过滤时两入口同一语义应一起出现；入口区分靠 `entity`（`delivery_task` vs `order`）。未采用 `COURIER_PICKUP_ORDER`：那会让「取货」语义分裂成两个 action，历史记录排查时容易漏看一半。
- `entity='order'`、`entityId=orderId`、`operatorId=courier.userId`
- `before: { orderStatus, taskStatus }` / `after: { orderStatus, taskStatus, taskId, allPicked }`
- 为取 `before.orderStatus` 在 transaction 前加一条**只读** `findUnique`（不参与任何业务判定）
- `after.orderStatus` 按 `updateMany` 实际条件（status ∈ {45, 40} → 50）镜像计算，不改状态流转本身
- 照本文件 `pickup()` 既有写法：audit 落在事务**外**、失败不回滚业务

**返回值 / 状态流转 / 权限：零改动**（接口原返回 `{orderId, picked, taskId, allPicked}` 原样保留）。
