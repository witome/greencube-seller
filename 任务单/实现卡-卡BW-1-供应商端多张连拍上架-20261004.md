## 三、逐屏实现口径（对齐原型 s1–s5）

### 画面1 · 入口（改 `goods-manage.vue`）
- 顶部 `row-btns` 里：原「＋ 提交新商品」**主按钮、交互与文案一字不改**；**并列新增**次按钮「📷 连拍上架（一次多张）」→ 跳 `batch-listing`。
- 老表单、老列表、老弹层全部**不许改**。

### 画面2 · 选图 + 串行处理（新页第 1 步）
- 大按钮「📷 拍摄 / 从相册选择（最多 9 张）」→ `pickPhotos({ count: 9 - 已选 })`。
- **串行**：`for (const p of paths)` 一张一张走「上传 → 识别」，**不许并发**；进度行「已完成 N / M」。
- 每格状态：`上传中…` / `识别中…` / `✅ 已填好` / `⚠️ 没认出来` / `❌ 上传失败`（失败格带「重试」；重试 = 重新上传+识别该张）。
- 「＋ 继续添加（剩余 K 张）」；满 9 张再点 → toast 原文「一次最多 9 张，多的请再发起一批」。

### 画面3 · 批量核对列表（新页第 2 步，**核心**）
- 汇总条：`共 N 条 · 可提交 X · 待补全 Y`。
- 每条卡：**收起**显示缩略图 + 名称 + 灰字 `供货价 ¥x/单位 · 日供 y单位` + 状态角标（`✅ 可提交` / `⚠️ 待补全` / `⬜ 未填`）；**展开**= 单条表单同款字段与顺序：商品名称 → 商品分类(chip) → 计量方式(chip) → 单位(chip) → 商品备注(≤12，带 `n/12`) → 供货价 → 日可供量 → 资质证明(缩略图网格 + ＋)。
- AI 预填的三项（名称/分类/计量方式）加**绿底**（沿用单条表单的 `ipt-ai` 类），用户一改就取消绿底。
- 缺必填的条目：红字点名（`请填写供货价` / `请填写日可供量` / `请选择商品分类` / `请填写商品名称`）并计入「待补全」。
- **字段只许多不许少**，不许新增任何字段（历史上因擅自加「起订量」被打回）。
- 分类与单位**必须是平铺可点 chip**，禁止下拉/`<picker>`。

### 画面4 · 提交（新页第 3 步）
- 底部固定「全部提交（X 条）」+ 每条卡内「单独提交」。
- 「全部提交」→ 二次确认弹层，文案照原型：`将提交 X 条商品，全部走运营审核（和单条提交一样）` / `待补全的 Y 条不会提交，会留在列表里` / 有共用资质时 `本批共用资质证明 × K 张`。
- 确认后**串行**逐条 `submitGoods`，每条回显 `⏳提交中…` → `✅已提交` / `❌提交失败 + 后端原因原样透出`（后端业务错照 `submit()` 的 catch 口径，别自己造文案）。
- 结果面板：`成功 X 条 · 失败 Y 条 · Z 条待补全未参与`；失败条可**单条重试**；已成功的**不回滚**；另有「返回商品列表」。

### 画面5 · 回显（回 `goods-manage`）
- 提交完成后回 `goods-manage` 并 `load()`，本批条目出现在**待审核**区。
- 「本批」标记：仅**本次会话内存内**给本批新提交的条目加一个角标+浅绿底（不落库、不改列表接口、不动后端）；离开页面即消失。
