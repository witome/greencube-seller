## 四、独立发现（含我修掉的 2 处）

1. **【已修】它自行新增了一个字段。** 画面4-② 的商品详情 mock 里画了一张「称重说明」卡片，内容被写成 `计量方式 / 起订量` 两行 —— 而**真机 `buyer/goods-detail.vue:22-25` 的这张卡只有一句** `{{ goods.weighNote || '称重商品按实际重量结算，多退少补' }}`，**「起订量」这个字段在工程里根本不存在**。原型＝视觉硬基准，多一行就会被当成需求实现，已改为真机口径那一句。
2. **【已修】数字笔误。** 后台单位表头写「共 **19** 条」，而表里只有 **18** 行单位（也正是卡里要求的 18 个预置），已改「共 18 条」。
3. **硬基准逐项对上（这才是"没跑偏"的硬证据）**：
   - 手机壳 `.phone { width:336px; height:648px; border-radius:26px }` 与 **卡BQ 原型逐字符相同**；
   - 主色 `#00B96B` ×15、`#F5F6F8` 页底、次文字 `#8A9099` ×14；
   - 买家端价格色 `.gc-price { color:#fa5151; font-size:16px; font-weight:700 }`、`.gd-price { color:#fa5151; font-size:22px }` **与真机 `buyer/goods.vue:356` 逐字符一致**（不是我一开始以为的"乱用红色"）；
   - chip 用 `border-radius:999px` + 选中态 `#E6F9F0/#00B578`，与小程序同款。
4. 一个**不算偏差但派实现卡时要写清**的点：原型里「商品分类」的标签是 `粮油/蔬菜/肉禽/水产/调料`（示意），真机里是**该供应商的授权分类**（如 时令蔬菜/猪肉/牛羊肉/禽蛋）。分类名来自接口，实现时不许写死。
5. 它把**卡BU 刚做出来的封面图双入口**（📷 直接拍 / 🖼 从相册选）也画进了同一张表单 —— 这是好事，说明新原型没有落后于刚入库的代码。
