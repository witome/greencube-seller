## 一、一句话

配送员发现**客户没给钱**时一键显式标记「客户未付款」；运营后台立刻看得到；**客户后来微信付了钱，标记自动失效**（线上到账永远优先）。

## 二、六条红线

1. 🚫 **不动钱**：不改订单金额、不改 `Settlement` 基数、不改账单、**不做任何扣款/抵扣**。
2. 🚫 **不新增表、不新增字段**：标记写进订单已有的 `order.pay_proof`（Json）里，加 `unpaidMark` 子对象。
3. ⚠️ **付款状态判定只走 `common/utils/pay-status.util.ts`** —— 页面/服务里禁止内联第二套判断。
4. ⚠️ **`unpaidMark` 不参与付款状态判定** —— 它只用于"提醒/展示"。判定优先级不变：`onlinePaid → paid_wechat` > `hasProof → paid_proof` > `cod_pending` > `unpaid`。
5. ⚠️ **不许改现有断言的期望值**（基线 **187/0** 是权威口径）。
6. ⚠️ **标记不推进订单状态**：订单仍停在「已送达(60)」（未付款的 COD 单停在 60 是有意为之）。

## 三、🔴 本卡必须先修的既有缺陷（原型阶段发现的真坑，别漏）

**`pay-status.util.ts` 的 `hasPayProof()` 现在写的是**：

```ts
const photos = (payProof as any).photos
return Array.isArray(photos) ? photos.length > 0 : true    // ← 不是数组就当"有凭证"
```

一旦 `payProof` 里加了 `unpaidMark`（没有 `photos` 字段），这里会返回 **true** → 该单被判成 **「已付款 · 扫码付款」** —— **钱一分没到，账却说已收**。

**修法（必须）：** 收紧成「**必须是非空 `photos` 数组**才算有凭证」，缺 `photos` 一律视为**没有**。

**安全性证据（已实测，写进交接页）：** 本机开发库 **9 行**、生产库 **4 行**带 `pay_proof` 的订单，**全部都有非空 `photos` 数组** → 收紧后**没有任何一行会从"已付款"翻成"未付款"**。

## 四、要做的事

### 1) 配送员端（小程序）

- **收款页** `frontend/src/subpkg-courier/pages/cod-pay.vue`：
  - 底部加**次要样式**按钮「**客户未付款**」（橙描边，**不许与「付款拍照」抢主色**）；
  - 页内写明：标记后客户侧显示「未支付」；**客户之后用微信付了会自动变已付款、标记自动失效**；
  - **已线上到账的单不显示这个按钮**（钱已到账，标记无意义）。
- **交付完成页** `subpkg-courier/pages/deliver.vue`：有 COD 待收款单时，把现在的「交付完成，请收款」toast 换成**半屏两路选择**：「客户已付款（上传收款凭证）」/「客户未付款」（跳二次确认）。
- **二次确认（半屏）**：一句确认 + **备注（选填，如"客户说下午转"）** + 「取消」/「确认标记」；确认后**回收款队列继续下一单**。
- **任务列表** `subpkg-courier/pages/home.vue`：已标记的单加**橙色小标「未收款」**（沿用既有 `cargo-claim-tag` / `cargo-online-tag` 的样式体系，新增 `cargo-unpaid-tag`）。
  - ⚠️ **标记只在配送员自己的列表可见**（客户侧不显示"谁标记的"，避免客户与配送员对线）。

### 2) 后端

- **新接口** `POST /courier/order/:orderId/unpaid-mark`（`@Roles(COURIER)`）：
  - 校验：订单存在、`payMethod === 2`（货到付款）、状态 ∈ {60}（已送达）；**已线上到账的单拒绝**；
  - 写入：`order.pay_proof.unpaidMark = { by: courierUserId, at: ISO 时间, remark: 备注或 null }`（**与现有 `photos`/`courierId`/`paidAt` 共存，不许覆盖掉已有 photos**）；
  - **状态不变**（仍 60）；写审计（action 自拟，交接页写明）；
  - body：`{ remark?: string }`（≤255 字）。
- **标记失效（改口）**：配送员**提交收款凭证**时（`courier.service.payProof()`，与凭证写入同一事务）**清掉 `unpaidMark`**。
- **`unpaidMark` 的读取口径抽成一处**（例如放 `pay-status.util.ts` 末尾 `readUnpaidMark(payProof)`），**三处消费都走它**：后台订单列表、后台对账、订单详情。
- **接口返回**：后台订单列表 / 对账 / 详情都要带上标记信息（`unpaidMarked: boolean` + `unpaidMarkAt` + `unpaidMarkRemark` + 标记人姓名，字段名自拟但交接页要写清）。

### 3) 运营后台（admin-web）

- **订单列表** `views/order/OrderFulfill.vue`（⚠️ **本卡实际文件名就是它，不存在 OrderList.vue**）：
  - 加**「收款标记」列**：命中时红色标签「配送员已标记未收款」+ 标记时间，**悬浮显示备注与标记人**；
  - 加**筛选**「仅看已标记未收款」；顶部统计块加一格「已标记未收款」；
  - 页面注明「收款标记 = 配送员显式标记"客户未付款"，**不代表已销账**」。
- **每日对账** `views/finance/DailyReconciliation.vue`：在既有「未收」口径上，把**配送员标记过的单单独标红**（红色行），并在「未收」卡片下加一行「**其中配送员已标记未收款 N 单 · ¥X**」。
- **订单详情弹窗**（在 `OrderFulfill.vue` 里）：「收款记录」时间线两行——
  - 橙色：配送员标记「客户未付款」· 时间 · 谁 · 备注；
  - 绿色（**仅当已线上支付**）：已由线上支付覆盖（**标记自动失效**）· 时间 · 微信直接支付 ¥X · 流水号；
  - 未发生线上支付时**只显示橙色那条**。
- **不做**：运营端「已收款/销账」按钮（2e，第一版不做）。

## 五、验收判据（每条都要可复现证据）

1. 配送员收款页出现「客户未付款」**次要**按钮；已线上到账的单**不显示**该按钮。
2. 点击 → 二次确认（备注选填）→ 确认后**库里有 `order.pay_proof.unpaidMark`**（含标记人/时间/备注），且**订单状态仍是 60**。
3. 标记后：**客户侧文案仍是「未支付」**；**运营后台订单列表出现红色标记**且「仅看已标记未收款」筛选能命中。
4. 标记后**客户线上支付成功** → 订单 **60→70**、客户侧变「已付款 · 微信直接支付」、**标记自动失效**（不再算"未收款"，但历史痕迹保留在时间线里）。
5. **改口**：配送员提交收款凭证后 → `unpaidMark` 被清掉。
6. 🔴 **`hasPayProof` 收紧后的判定**：构造「只有 `unpaidMark`、没有 `photos`」的 `pay_proof` → 该单判 **「未支付」**（**不许**判成「已付款 · 扫码付款」）；有非空 `photos` 的行仍判「已付款 · 扫码付款」。
7. **老数据不翻车**：库里已有的带 `pay_proof` 的行（开发库 9 行 / 生产 4 行，均有 photos）判定结果与改动前**一致**。
8. **钱一分没动**：改动前后 `Settlement`/账单/订单金额字段**逐字段相等**；结算单仍能生成。
9. 基线 `cd backend && npm run build && node 验收测试.js` → **187 通过 / 0 失败**；`npx tsc --noEmit` → **0 错**；`admin-web` 与小程序两端构建通过。
10. 新增自测脚本 `backend/scripts/unpaid-mark-test.js`（**必须自己加载 `backend/.env`**），覆盖 1~8；**自带清理**并断言「残留 = 0」。
