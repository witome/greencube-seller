## 四、口径说明（拍板）

- **台账**：不加表（本卡 schema 只许两列），每一通拨打写一条 `audit_log`（action=`SUPPLIER_NOTIFY_CALL`，`after` JSON = `{orderId,supplierId,mode,result,callId,note,dryRun,at}`）；接口 4 读它，卡BN-2 的「已处理」按钮打接口 7。审计与台账同源，不重复写。
- **`lastResult` 的 skipped_* 推导**：列表实时推导（无台账时按 扫描同序：自关 > 无手机号 > 免打扰），有台账则用台账结果；扫描时的 skip 不逐条落台账（每分钟扫一次会刷爆审计）。
- **人工补打不占自动次数**：`manualCall` 不动 `remindCount/lastRemindAt`，自动拨打次数只由扫描计。
- **`minutesUnacked`**：当前时间 − 订单创建时间（与卡BJ 运营后台口径一致，不用会漂移的 updated_at）。
- **`todayStats.needManual`**：当前未接单、未 stopped、`remindCount>=maxCalls` 且订单仍备货中的去重订单数。
- **错误响应实测口径**：BizException → HTTP 200 + 业务码（1001 参数错 / 2002 无权限）；仅 ValidationPipe 拦下的入参（如 `quietStart:"25:99"`）是原生 HTTP 400。卡BN-2 前端按「`code!==0` 即失败」处理即可。
