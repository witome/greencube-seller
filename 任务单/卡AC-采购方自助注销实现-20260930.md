## 一、业务口径（已拍板，不许改）

1. **只有采购方能自助注销**（供应商/配送员不在本卡范围）。
2. **注销前必须两项都清空**：
   - ① **进行中订单**：存在 `order.status ∈ {10,20,30,40,45,50}` 的订单；
   - ② **未结清账款**：存在「已进入应收状态（`status ∈ {60,70,90}`）」且**支付状态为未支付/待收款**的订单。
     ⚠️ **支付状态一律复用 `backend/src/common/utils/pay-status.util.ts` 的既有四档判定，禁止另写一份**（这是本项目反复出事的点）。
     ⚠️ **不许用 `buyer.service.bill()` 当判据** —— 那是个占位实现（`paidAmount` 恒为 0），会把所有买过东西的采购方全拦住。
3. **注销动作（一个事务内全部完成）**：
   - `user.name`、`user.phone` 置 null；
   - `purchaser` 的 PII 匿名化：`shopName` → `已注销账号`，`contact` / `phone` / `address` 清空，`qualification` / `businessLicenseNo` / `businessLicenseImg` / `foodPermitImg` / `deliveryWindows` 清空；
   - 清空该采购方的 `cart_item`；
   - `purchaser.accountStatus = 6` —— **新增常量 `AccountStatus.CANCELLED = 6`（语义「已注销（本人自助）」）**，与 5「运营停用」区分开（两者在前端提示与后台筛选里是不同状态）；
   - **解绑（关键）**：新建一个「回收站」用户行（`wx_openid = 'cancelled_' + 随机不可猜串`、`name='已注销'`、`roles=[]`、`status=0`），把**旧 purchaser 行的 `userId` 改指到这个回收站用户**。
     - 目的：原微信用户从此**没有 purchaser 档案** → 可以**重新注册成全新账号**；历史订单仍挂在旧 purchaser 行上（对账/税务完整），但**不再关联本人**（这就是原型「历史订单不跟过来」的实现方式）。
     - ⚠️ **不许动 `Purchaser.userId` 上的 `@unique` 约束、不许改 `schema.prisma`**：全仓有 **33 处** `purchaser.findUnique({ where: { userId } })`，一旦放松唯一性这 33 处全部要改，风险不可接受。本方案正是为了保住这个约束的语义。
   - 写审计：`BUYER_ACCOUNT_CANCEL`（`entity='purchaser'`，before/after 只记 `accountStatus` 与「已匿名化」摘要）。
     ⚠️ **审计里绝对不许出现姓名 / 电话 / 执照号 / 地址**。
4. **注销只作用于「采购方身份」**：若该微信还有其它身份（供应商/配送员），账号本身保留、其它身份一切不受影响。
5. 注销后同一微信登录：登录正常，但**没有 purchaser 档案** → 前端走注册流程，重新走一遍注册 + 审核，作为全新账号。

## 二、接口（两个，都 `@Roles(Role.PURCHASER)`）

| 接口 | 语义 |
|---|---|
| `GET /buyer/account/cancel-eligibility` | 返回 `{ canCancel, blockers: [{ type: 'orders'|'bill', count, amount, label }] }`；`type='orders'` 的 label 例「你还有 2 个进行中的订单」，`type='bill'` 例「你还有未结清账款 ¥386.50」 |
| `POST /buyer/account/cancel` | body `{ confirm: true }`（**必须显式 confirm，缺了或 false → 参数错**）。不满足条件 → 业务错并回 `blockers`；成功 → `{ cancelled: true }` |

- 成功路径返回后，前端负责清本地登录态。
- 两个接口都要能在**没登录/非采购方**时按既有约定回业务码（别裸 500）。

## 三、前端（照原型 5 屏）

1. `pages/buyer/mine.vue`：底部（退出登录下方）加**红色文字入口「注销账号」**，并在旁边用一行小字与「退出登录」区分（原型屏①的红线块：退出登录只是退出、资料还在；注销是删除账号）。
2. 新页 `pages/buyer/account-cancel.vue`（`pages.json` 注册），**一页承载原型屏②~④**：
   - 屏②两种态按 `cancel-eligibility` 渲染：不满足 → 列出 blocker（右侧「去处理」跳 `/pages/buyer/order-list` 或 `/pages/buyer/bill`），底部「注销账号」**置灰**；满足 → 绿色「当前可以注销」+ 红色「申请注销」可点。
   - 屏③二次确认：4 条后果逐条列出（个人信息清空 / 历史订单账单依规保留但不再关联本人 / 进行中订单与未结清账单须先处理完 / 注销后同微信可重新注册但需重新审核、历史数据不恢复）+ 勾选框「我已知晓以上后果」→ **勾选后「确认注销」才可点**；另有「再想想」返回。
   - 屏④成功态：「账号已注销」+ 3 条对勾 + 「重新注册」（跳 `/pages/buyer/register`）与「先不注册」（回浏览态，该态价格显示规则同「未注册看价」）。
   - 进入本页时**若账号是停用态(5)** 应被既有 `account-guard` 拦到停用页（本页不该出现注销入口）。
3. 注销成功后：清 storage（token / 身份记忆等，复用既有退出登录那套清理，**不许另写一份**）→ `reLaunch` 到浏览态。
4. `account-suspended.vue`（停用页）**不要加注销入口**，别顺手改。
