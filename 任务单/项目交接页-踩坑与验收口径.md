## 二、铁律（都是踩过才定下来的，别再造第二套）

1. **同一口径只有一份实现**：金额口径（`common/utils/amount.util.ts` + 前端 `utils/order-amount.js` 语义相同）、采购需求归一化（`demand.util.ts`）、订阅字段格式化（`wx.format.ts`）、AI 草稿合并（`ai/parser/draft.ts`）。改口径先找那份唯一实现。
2. **`POST /api/v1/ai/parse` 必须只读**（只 `findMany` 商品、不写库）——所有生产只读探针都靠它。要落库的副作用由前端**另调接口**。
3. **契约只增不改**：响应字段只新增，不动既有字段语义；前端老行为（不传新参数）必须与改动前逐字节一致。
4. **口径以原型为准**：大辉用 HTML 原型当图纸，**严禁自行发挥偏离**；与原型不一致时停下来问。
5. **凭据全程掩码**：`.env` / AppSecret / token **不打印、不进对话、不进日志**；改 `.env` 前先 `cp` 备份，**不许用 patch 工具改 `.env`**（会把值回显）。
6. **AI 上下文/草稿**：模型只回操作（add/set/remove/clear），**合并由服务端做**，前端只显示。
7. **采购需求 ≠ 下单后缺货**：`purchase_demand*` 是「客户还没下单、我们压根没这个菜」；`order_item.qty_accepted` 是「已下单、到货不够」。两条独立线。
8. **微信订阅消息**：模板 id 只从 `.env` 读、字段名靠 `gettemplate` 自动探测、发送值按类型格式化（`thing`≤20 字 / **`amount` 首位必须币种符号 → `¥5.80`** / `number` 纯数字）。**绝不把 `47003` 甩给运营**；额度**只在微信返回 ok 时 −1**。
9. **到货商品不自动上架**：价格/规格由大辉确认，手动上架 + 后台一键通知。
10. **真实登录已上线**：`WX_APPID`/`WX_SECRET` 是真凭证，`WX_MOCK_LOGIN=0`，**别改回占位值**。

## 三、部署硬流程（少一步就会出「部署了但没生效」）

1. **改前先备份**：`sh /usr/local/bin/lvlifang-backup.sh`，并**用内容自检**（`gunzip -c <dump> | grep -c "INSERT INTO"` > 0，且能找到业务表如 ``INSERT INTO `order` ``）——「文件存在 + 能解压」不算。
2. 本地构建（**2G 机器上不许编译**）：`backend && npm run build`（先 `rm -rf dist tsconfig.tsbuildinfo`，`nest build` 是增量的，不删可能直接跳过）、`admin-web && npm run build`。
3. 旧产物**先改名再解包**：`mv dist dist.old-<ts>` → 解包 → 验证通过后再删。
4. 传了新 `prisma/` 就要在服务器上 `npx prisma generate` + `npx prisma migrate deploy`。**手写迁移在服务器上是真执行 SQL**，所以每个迁移都要**全新环境可跑**（纯 CREATE TABLE 那类）。
5. `pm2 restart lvlifang-api` → `pm2 list` 看 online → 看 err 日志。
6. **判版唯一硬证据 = 产物 md5 逐字节比对**（比本次改动所在的模块文件，**不能拿 `backend/dist/main.js`**，那是个 1.6KB 引导文件、跨版本 md5 可能相同）。
7. **结论性验证一律在服务器本机跑**（本机 curl 会吃到代理缓存）。
8. **探针要零副作用**：只读接口可以真跑；有写操作的接口改用**反例探针**（发非法值 → 期望被拒 → 校验失败即天然没落库），别为了验功能往生产库造业务数据。

## 六、踩坑清单

### 6.1 本会话新增（2026-09-25）

- **端口「被占着」比「没人听」更阴**：你的实例 `EADDRINUSE` 起不来，请求被上一轮遗留的实例**默默接走**（它的 `.env` 是旧的）→ 一套本来全绿的脚本会在毫不相干的地方崩。复跑前确认端口属主，杀用 `powershell Stop-Process -Id <pid> -Force`（`taskkill //PID` 在 MSYS 下会失败）。
- **别拿 `$!` 与 Windows PID 比「属主是不是我起的」**：MSYS bash 的 PID 与 Windows PID **不同域**、永远不等。
- **别信「服务都在跑」这句口头结论**（无论来自写代码的一方还是它的收尾报告）：沙箱会在任务结束后回收它拉起的进程（约 6~7 分钟延迟），所以它刚跑完时那些进程往往还活着。
- **被取消的会话通常续不了**：提示「已取消 / 授权超时未确认」后**输入框是禁用的**（点击 + 粘贴 + 打字都进不去）。处置 = 另开一张「续做卡」，卡里写明「工作区已改好、不要推翻」的文件 + 「先 `git status/diff` 看清现状」。⚠️ 但**别假设「没有新 commit = 它没干活」**——实测它被取消后又自己恢复并提交了。
- **时区：`NOW(3)` 是坑**。手写 SQL 写 datetime 用 `NOW(3)`，MySQL 会话是 +08 而 Prisma 按 UTC 读 → **整列偏 8 小时**（库里看是对的、接口看差 8 小时）。统一用 **`UTC_TIMESTAMP(3)`**。排查先比「库里值 vs 接口返回值」。
- **`自测证据/` 不入库**（`.gitignore` 已排除）：派卡时要写「只 `git add` 具体源码文件」。
- **微信 `amount` 字段要带币种符号**：官方正则是 `^[A-Za-z$€¥]{1}[\d]{0,8}(\.\d{1,2})?$`，纯数字会被判格式错 → 发 `¥5.80`。
- **官方 `gettemplate` 不返回 kid 数组**：字段名只能从模板 `content` 的 `{{xxx.DATA}}` 里解析。

### 6.2 高频老坑（都真踩过）

- **`search_files`（ripgrep）对 `backend/src` 的内容搜索会返回 0 命中**（还默认跳过 gitignore 的 `dist/`）→ 查代码一律用 shell 的 `grep -rn`，别据 0 命中下「没有这段代码」的结论。
- **bash 向 native 程序传中文会按 GBK 乱码** → 中文请求体**先写文件**再 `curl -d @file`；中文断言用 node 的 `\uXXXX` 转义。
- **「只处理了一种情况」是这个项目最高频的缺陷家族**：修一处调用点/页面，先 `grep` 出全部兄弟节点一起修，并抽成唯一共享实现。
- **`prisma db push` 直改结构 = 迁移漂移**，任何全新部署首次登录就 P2022。改结构必须生成迁移文件。
- **写 `NOW(3)` / 手写迁移**：见 6.1。
- **「页面存在」≠「流程接上了」**：`grep -rn "pages/<某页>" frontend/src | grep -v pages.json`，只匹配到定义、匹配不到跳转就是死页面。
- **new 记录默认排最后一页 = 用户以为「后台没收到」**：凡「用户提交完要去后台看」的列表，**新记录必须在第一屏**；预警类信号用卡片/徽标，别用排序表达。
- **云托管日志只能证明「请求发出去了」**：业务错误一律 HTTP 200 + body 里业务码 → 满屏 200 不等于流程走通。
- **Windows 上 GNU tar 要加 `--force-local`**（否则 `C:` 被当远程主机）。
