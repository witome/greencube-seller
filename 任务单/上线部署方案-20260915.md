# 辉崧鲜配 · 上线部署方案

> 面向:大辉(非程序员,照着一行一行做即可)
> 日期:2026-09-15
> 前提:域名备案 ✅ 已通过;后端能打生产包 ✅ 已实测(`nest build` 通过,产物 `dist/` 1.9M)

---

## 一、整体架构(谁连谁)

```
   采购方/供应商/配送员                运营人员
   微信小程序(手机)              运营后台(电脑浏览器)
            │                             │
            └──────────┬──────────────────┘
                       ▼
          https://api.你的域名          ← 小程序强制要求 https
                       ▼
              ┌─────────────────┐
              │   nginx(服务器)  │  ← 80/443 端口对外
              └────────┬────────┘
                       ▼
              Node 后端(3001,只监听本机)
                       ▼
              MySQL 8.4(服务器本地)
```

**关键点**:小程序**不能**连局域网,也不能连 http —— 必须 **https + 已备案域名**。这就是为什么必须走这一步。

## 二、服务器上要装 5 样东西

| 装什么 | 干什么用 | 装法 |
|---|---|---|
| **nginx** | 接收外部请求、配 https | 宝塔一键 / `apt install nginx` |
| **Node.js 20 LTS** | 跑后端 | 见下 |
| **MySQL 8.4** | 数据库 | 宝塔一键 / 官方源 |
| **pm2** | 让后端 24 小时不挂、开机自启 | `npm i -g pm2` |
| **https 证书** | 小程序强制要求 | 宝塔一键免费证书 / acme.sh |

> **如果服务器上有「宝塔面板」**:上面 4 样基本都能在面板里点着装,后面步骤也都有图形界面,最省事。
> **如果没有**:建议先装宝塔(一条命令),或者照第三节的命令行版本做。

## 二之二、⚠️ 你的机器是 2 核 2G —— 这 5 处必须专门调整

**2 核 2G 跑这套是够的**(你的量级完全撑得住),但内存很紧,下面这几条**不做就会中途失败**:

### ① 先加 2G 交换分区(swap)—— 最要紧的一条
2G 物理内存遇到 `npm ci`、数据库导入这种瞬时高峰会直接杀掉进程。加 2G swap 相当于给内存上个"缓坡":

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab    # 开机自动挂载
free -h                                             # 确认 Swap 那行有 2.0Gi
```

### ② 不要在服务器上「构建」,在你自己电脑上构建好再上传
`nest build` 和 `npm run build`(vite)编译时要吃 1G+ 内存 —— **2G 机器上编译极可能崩**。

**做法:**
- 在**你这台电脑**上先跑 `npm run build`(后端、运营后台各一次)
- 把产出的 `backend/dist/` 和 `admin-web/dist/` **上传到服务器**
- 服务器上**只**做:`npm ci`(装依赖,不吃编译内存)+ `npx prisma generate`(下 Linux 版引擎)

> ⚠️ 注意:`node_modules` 不能直接从 Windows 拷过去 —— Prisma 的引擎是分平台的,必须在服务器上 `npm ci` 重装一次。

### ③ MySQL 必须调优(默认配置是按大机器写的)
在 MySQL 配置里加/改这几项,能省下 **300~500MB 内存**:

```ini
[mysqld]
performance_schema = OFF          # 最关键,默认开着要吃掉几百 MB
innodb_buffer_pool_size = 256M    # 默认偏小,给到 256M 够用
max_connections = 50              # 默认 151 太多,按实际需求降到 50
```

### ④ 别装 Docker
Docker 在 2G 机器上光自身就吃掉一两百 MB。**直接用系统原生安装**,不要为了"方便"上 Docker。

### ⑤ 给后端加内存上限保护 + 开 gzip
```bash
# pm2 启动时加上内存上限:超过 500M 自动重启,避免内存泄漏把整台机器拖死
pm2 start dist/main.js --name lvlifang-api --max-memory-restart 500M
```
nginx 里加 `gzip on;`(省流量、也让小程序加载快些)。

> **宝塔面板要不要装?** 可装可不装 —— 它自己占 100~200MB 内存,但换来的是图形界面。
> 你这台机器**装得下**,图省事就装;想省内存就走纯命令行(我给你的命令都能直接粘)。

## 三、部署步骤(按顺序,别跳步)

### 第 1 步:域名解析(在你买域名的后台做)
加两条解析记录,都指向服务器 IP:

| 记录 | 用途 |
|---|---|
| `api.你的域名` | 后端接口(小程序请求它) |
| `admin.你的域名` | 运营后台(你电脑浏览器打开它) |

做完等 10 分钟,用 `ping api.你的域名` 验证:能解析到你的服务器 IP 就对了。

### 第 2 步:申请 https 证书
- **宝塔**:站点 → SSL → Let's Encrypt 免费证书 → 一键申请 + 自动续期
- **命令行**:用 `acme.sh` 申请

⚠️ **小程序只认 https,而且是可信证书** —— 自签名证书不行。

### 第 3 步:装 Node + pm2
```bash
# 装 Node 20
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v          # 应显示 v20.x

# 装 pm2(进程守护)
npm i -g pm2
```

### 第 4 步:建数据库
```sql
CREATE DATABASE lvlifang DEFAULT CHARACTER SET utf8mb4;
CREATE USER 'lvlifang_app'@'localhost' IDENTIFIED BY '你的强口令';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,DROP,REFERENCES,INDEX,ALTER
  ON lvlifang.* TO 'lvlifang_app'@'localhost';
FLUSH PRIVILEGES;
```
> ⚠️ **权限清单要跟本地一致**(本地就是这几个权限 —— 少一个 `ALTER` 就会像我们之前踩过的坑一样,迁移跑不动)。

### 第 5 步:上传代码
```bash
mkdir -p /www && cd /www
git clone <你的代码仓库地址> lvlifang     # 或打包上传后解压
cd lvlifang/backend
```

### 第 6 步:配置后端环境变量
在 `backend/` 下建 `.env`(照本地那份改,**值全部要换**):

| 变量 | 线上要填什么 |
|---|---|
| `DATABASE_URL` | 指向服务器本地 MySQL + 第 4 步的口令 |
| `JWT_SECRET` | **重新生成一个随机长串**(别用本地那个) |
| `WX_APPID` / `WX_SECRET` | **真实值**(小程序后台 → 开发管理 → 开发设置) |
| `WX_MOCK_LOGIN` | **`0`**(关了模拟登录) |
| `WX_MOCK_PAY` | 支付商户号到位前**先保持开启**,到位后设 `0` |
| `PAY_CALLBACK_SECRET` | 重新生成随机串 |

> ⚠️ 这几个值是密钥,**不要发给任何人、不要贴到任何"项目"协作空间里**。

### 第 7 步:上传构建产物(2G 机器不在服务器上编译)
**先在你这台电脑上**(Windows)把两个都构建好:
```bash
cd C:/Users/Administrator/Documents/绿立方开发/backend    && npm run build
cd C:/Users/Administrator/Documents/绿立方开发/admin-web  && npm run build
```
然后把 **`backend/dist/`** 和 **`admin-web/dist/`** 上传到服务器对应目录(用宝塔的文件管理、或 `scp`)。

### 第 8 步:服务器上装依赖 + 建表
```bash
cd /www/lvlifang/backend
npm ci --omit=dev              # 只装运行依赖(开发依赖不装,省内存省磁盘)
npx prisma generate            # 下 Linux 版查询引擎(必须在这一步做,不能从 Windows 拷)
npx prisma migrate deploy      # 按迁移文件建全部表
# 初始数据(分类/商品/账号等)按你们自己的初始化脚本导入
```

### 第 9 步:用 pm2 拉起来
```bash
pm2 start dist/main.js --name lvlifang-api --max-memory-restart 500M
pm2 save                       # 记住当前进程列表
pm2 startup                    # 开机自启(按提示再粘一条命令)
pm2 logs lvlifang-api          # 看日志,确认起来了
```

### 第 10 步:发布运营后台
```bash
cd /www/lvlifang/admin-web
npm ci && npm run build        # 产出 dist/
# 把 dist/ 交给 nginx 作为静态目录(见第 10 步)
```
> 运营后台**不能**再跑 vite dev(那是开发模式),线上必须是 build 出来的静态文件。

### 第 11 步:配 nginx(最关键的一步)
两个站点:

**`api.你的域名`** —— 反代到后端
```nginx
server {
    listen 443 ssl http2;
    server_name api.你的域名;
    ssl_certificate     /path/证书.pem;
    ssl_certificate_key /path/证书.key;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**`admin.你的域名`** —— 静态文件
```nginx
server {
    listen 443 ssl http2;
    server_name admin.你的域名;
    ssl_certificate     /path/证书.pem;
    ssl_certificate_key /path/证书.key;

    root /www/lvlifang/admin-web/dist;
    index index.html;

    # 运营后台的接口调用(前端用相对路径 /api/v1)
    location /api/v1/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 上传的图片(收款码 / 交付照片 / 付款凭证 / 营业执照)
    # ⚠️ 必须加:图片存的是相对路径 /uploads/xxx,浏览器会拿它去 admin 域名要;
    #    不反代就会被下面的单页应用兜底返回 index.html,页面显示「加载失败」。
    #    (2026-09-19 线上实际踩过:开发环境有 vite 代理所以本地正常,线上才挂)
    location /uploads/ {
        proxy_pass http://127.0.0.1:3001;
    }

    location / {
        try_files $uri $uri/ /index.html;   # 运营后台是单页应用,刷新不能 404
    }
}
```
(两个都再加一个 80 端口的 server 块,把 http 跳转到 https。)

### 第 12 步:安全组 / 防火墙
- **放开**:80、443
- **关掉**:3001(后端只给 nginx 访问,**绝不能对公网开**)、3306(数据库)
- 云服务器后台的「安全组」也要同步改(这是最常忘的一步)

### 第 13 步:自动备份(别省)
```bash
# 每天凌晨 3 点自动备份数据库,保留 30 天
0 3 * * * mysqldump -u lvlifang_app -p'口令' lvlifang | gzip > /backup/lvlifang_$(date +\%F).sql.gz
```
> ⚠️ **备份文件要存到服务器之外**(对象存储/另一台机器)。只存在同一台服务器上,机器一坏备份也一起没了。

## 四、微信公众平台后台要配什么

| 配什么 | 位置 | 说明 |
|---|---|---|
| **服务器域名** | 开发管理 → 开发设置 → 服务器域名 | 填 `https://api.你的域名` 到 **request 合法域名**。**必须有 https + 已备案** |
| 业务域名 | 同上 | 如果小程序里要打开网页才需要 |
| 隐私协议 / 用户协议 | 设置 → 服务内容声明 | 提审必查 |
| 小程序备案 | 设置 → 基本设置 | **进行中**(不完成不能上架) |
| 提审材料 | 版本管理 → 提交审核 | 类目、功能页截图、测试账号 |

## 五、上线前的开关清单(逐项打勾,别漏)

| # | 检查项 | 线上必须是 |
|---|---|---|
| 1 | 后端 `WX_MOCK_LOGIN` | `0` |
| 2 | 后端 `WX_APPID` / `WX_SECRET` | 真实值 |
| 3 | 前端请求地址 | `https://api.你的域名/api/v1`(**不能是局域网 IP**) |
| 4 | 前端 mock 登录开关 | 关 |
| 5 | **调试浮窗（`DevRoleSwitcher` / App.vue 注入的 🎭）** | **正式包里不出现** —— 已由构建护栏强制：`npm run build:prod:mp` 会校验「产物里没有 `demo_supplier`（浮窗代码已删净）」，不过就退出码非 0 |
| 6 | `JWT_SECRET` / `PAY_CALLBACK_SECRET` | 重新生成,别用本地值 |
| 7 | 后端 3001 / 数据库 3306 | 不对公网开放 |
| 8 | 自动备份 | 已配 + 验证过能恢复 |
| 9 | 支付 | 商户号未到位就先保持模拟,到位后切 |
| **10** | **后端 `WX_MOCK_PAY`** | **`0`** ⚠️ **必须关** —— 开着的话,**任何采购方都能自助把订单标记成「已付」**。2026-09-19 大辉测试期同意先留着,**正式上线前务必关掉**(改 `backend/.env` 的 `WX_MOCK_PAY=0` → `pm2 restart lvlifang-api`) |
| **11** | **小程序出货包怎么出** | **只能** `cd frontend && npm run build:prod:mp` —— 自动带 `https://api.hsfresh.com/api/v1`，并**自动校验 4 项**：接口地址是生产域名 / 产物里没有局域网地址 / 调试浮窗已删净 / appid = `wx82f6deee9c7750e4`；任一项不过就退出码非 0。🚫 裸跑 `npm run build:mp-weixin` 已被 `prebuild` 钩子拦住（它会先清空出货目录，所以必须拦在前面）；自测一律用 `npm run build:self:mp`（产物 `dist/self/mp-weixin`，与出货目录物理隔离，**不可上传**） |
