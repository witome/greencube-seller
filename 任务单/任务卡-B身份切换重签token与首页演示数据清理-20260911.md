## B（最高优先）：身份切换没重签 token —— 已修 ✅

### 修前事实（勘查确认，比卡描述更细一层）

- `frontend/src/store/user.js:31-40` switchRole：只有 `// TODO: api.auth.switchRole(role) -> 新 token`，**只改本地 currentRole 就 reLaunch**（属实）
- `api/modules.js:10` switchRole 接口早已注册，store 里没被调用（属实）
- 后端守卫读 **JWT 里的 currentRole**（`roles.guard.ts`）→ 切换后界面跳了、判权没换（属实）
- **补充发现 ①**：`store/user.js` 的 switchRole **实际无调用者**。真实入口是三个 mine 页（buyer/supplier/courier）各自的本地 `switchRole`——它们**已调** `/auth/switch-role` 换 token，但**无失败处理**（抛错静默、无提示）、**不清业务缓存**。即真 bug 由两条不完整路径叠加构成。
- **补充发现 ②**：H5 调试浮窗（`App.vue` 🎭 切换角色）走的是**重新 mock 登录成另一个 dev 账号**（不同 openid 不同用户），不是「同账号身份切换」，语义不同，本卡未动。

### 修复内容

1. **`store/user.js`**：switchRole 改 async，完整落实决策 4：
   - ① 调 `/auth/switch-role` 换新 token（失败向上抛，**拿到新 token 前不做任何本地变更、不跳转**）
   - ② 新 token + currentRole 同步写 store 与本地缓存
   - ③ 清空业务缓存（`aiDraft` AI 会话草稿 / `registeredRole` / `account_status` 注册流程残留；本地无购物车/订单列表缓存，均为接口拉取）
   - ④ 按新身份 reLaunch 对应首页
2. **三个 mine 页**（`pages/buyer/mine.vue`、`subpkg-supplier/pages/mine.vue`、`subpkg-courier/pages/mine.vue`）：本地 switchRole 删除，统一改调 `useUserStore().switchRole()`，try/catch 包裹——**失败时 request 层已 toast，页面保持原身份不跳转**。（⚠️ mine 页不在卡面点名清单内，但它们是切换真实入口，不改则修复无法生效——必要最小扩散，特此说明）

### 决策 4 对照：哪几句现在才算真正落实

| 决策 4 原文要点 | 修前 | 修后 |
|---|---|---|
| 「切换身份必须**重签 token**」 | store 路径完全不签；mine 路径签了但无失败处理 | ✅ 两条路径统一走 store 重签 |
| 「新 token 以**当前身份**签发，守卫按 JWT 判权」 | 界面切了、JWT 没换 → 全 2002 或反向越权 | ✅ 新 token payload.currentRole 已实测变化（见下） |

| 「失败不得把界面切到一半」 | mine 路径抛错静默；store 路径无条件跳 | ✅ 失败不跳转 + toast，原身份原页面 |
