## 配套的规范工作循环

```
挑选下一张卡  →  出任务卡（等确认）  →  实现  →  自验 + 出证据  →  写日志 + commit  →  下一张
```

一次只推进一张卡的好处：会话不会失控膨胀、每步都有证据可查、出问题只需回退一张卡。

## 完成定义（Definition of Done）

一张卡只有同时满足以下条件才算完成，**未验收不勾完成**：

- [ ] 功能按原型实现（原型没有的，按后台既有视觉规范）
- [ ] 自动测试或接口验证通过
- [ ] **真实浏览器 / 真机**操作过一遍（接口冒烟不能冒充页面验收）
- [ ] 改动没有溢出到其他端/其他页面
- [ ] 证据落盘到 `自测证据/`
- [ ] 写进当天 `.workbuddy/memory/` 日志
- [ ] `git commit`（不 push）
