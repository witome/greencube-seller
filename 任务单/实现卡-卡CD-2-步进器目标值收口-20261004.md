## 一、问题（Hermes 在 H5 真浏览器实测复现，数字如下）

```
初始 5 → 连点 3 次「＋」 → 界面 8 / 服务端 8        ✅ 卡CD 已修好（不许弄坏）
外部把服务端改成 20（等价于「AI 助手说：土豆改成20斤」）
→ 离开页面再回来（onShow → load()）：界面仍是 8，服务端已是 20   ❌ 界面≠真值
→ 再点一次「＋」：服务端被写成 9（把 20 覆盖掉）                  ❌ 覆盖真值
```

**根因**（`frontend/src/pages/buyer/cart.vue`，卡CD 新增的那段）：

```js
const targetQty = reactive({})   // cartItemId -> 本地目标数量：一旦写入，永不清除
const rowBusy = {}               // cartItemId -> 该行 PUT 在飞
...
const flushRow = async (id) => { ...
      if (Number(row.qty) === target) break   // ← 服务端已追上目标，只 break，没有清 targetQty
      ...
}
```
而渲染与下一次计算都优先用它：
```html
<text v-else class="stp-n" @tap="startQtyEdit(it)">{{ targetQty[it.cartItemId] != null ? targetQty[it.cartItemId] : it.qty }}</text>
```
```js
const base = targetQty[id] != null ? Number(targetQty[id]) : Number(it.qty)
```

⇒ 本地旧目标值既骗了显示、又当了下次覆盖的基准。**违反项目口径「服务端是唯一真源」。**

## 三、要的行为（口径写死）

**总原则：本地目标值只是「用户还没被服务端确认的那个意图」的临时占位；一旦该行没有在飞的请求，服务端值就是真值，本地目标值必须立刻失效。**

1. **收敛即清**：`flushRow` 里发现「服务端 `qty` == 本地目标」时，除了 `break`，还要 `delete targetQty[id]`。
2. **每次 `load()` 之后清「不在飞」的行**：新增一个同步收口（例如 `syncTargetsAfterLoad()`，在 `load()` 拿到服务端数据后调用）—— 遍历 `targetQty` 的每个 id，
   - **该行在飞（`rowBusy[id]` 为真）→ 不动**（那是用户正在进行的点击，绝不能被丢掉）；
   - 否则 `delete targetQty[id]`（该行已无未确认意图，显示与基准都回到服务端真值）。
   ⚠️ 这一条正是让「AI 助手改量 / 另一台设备改量」能正确反映到界面与后续操作的关键。
3. **既有行为一条都不许弄坏**：
   - 连点 N 次「＋」仍要**立刻** +N（界面不闪回），最终服务端 = 原值 + N；
   - 同一行的 PUT 仍**串行**（同一时刻只有一个在飞）；
   - 失败重试耗尽仍**回滚**到服务端真值（现在靠 `delete targetQty[id]`，保持）；
   - 数量减到 0 仍走既有 `remove(it)`；
   - **金额/合计仍只认服务端**（`GET /cart` 的 `totalAmount` / `subtotal`），不许在前端算价；
   - `uni.$emit('cart-badge-refresh')` 保留。
4. **不许把 `targetQty` 落成 storage/持久化**（它就是内存态）；页面 `onUnload` 时清空它与 `rowBusy` 即可（防下次进页面拿到上一轮的残留）。
