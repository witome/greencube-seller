## 一、一句话

供应商超时没接单 → **云端判定谁该打** → **你电脑上的小助手指挥一部专用安卓手机拨给该供应商** → 响 5 秒挂断 → **结果回写催单台台账**。

## 二、为什么走这条路（都是大辉已定的口径）

| 已定的事 | 原因 |
|---|---|
| 前期**不要语音、只要"响一下"** | 云语音做不到"只响铃不说话"（运营商要求播报内容报备）；手机可以，且 0 成本 |
| **专号卡与客服号分开** | 客服号不被自动化外呼牵连；供应商回拨语义清楚 |
| 专号**只拨出、不接电话、不做呼叫转移** | 回拨问题用文案解决（"本号仅作提醒，请勿回拨，有事拨客服 XXX"） |
| 号码让供应商**存成「辉崧鲜配新订单提醒」** | 来电显示认得出来，不会被当骚扰忽略 |

## 三、现在的家底（已建好，**不重做**）

## 四、新架构：谁干什么

```
┌──────────────── 阿里云（现有后端，不改架构） ────────────────┐
│  ① 每分钟扫描：谁超时没接单、该不该打（现有逻辑，原样用）      │
│  ② 把"该打的"放进待拨队列（新增）                             │
│  ③ 收结果 → 写催单台台账（新增通道字段）                       │
└──────────────────────────▲──────────────┬───────────────────┘
                   ③回报 │              │ ②每 30 秒来问一次（本机主动出去，家里不用开公网口子）
┌──────────────────────────┴──────────────▼───────────────────┐
│  你电脑上的「手机网关」（新增，常驻小程序）                     │
│  拿号码 → 指挥手机拨号 → 读系统日志判"接没接" → 回报            │
└──────────────────────────┬───────────────────────────────────┘
                           │ USB 数据线（adb）
                  ┌────────▼────────┐
                  │  专用安卓手机     │  只干一件事：拨号 + 响 5 秒挂断
                  │ （提醒专号卡）    │
                  └─────────────────┘
```

要点：**云端在公网、手机在家里** ⇒ 由本地主动去问云端（出站），不需要给家里路由器开端口，也不用固定公网 IP。

## 五、要新增/改动的东西（逐项）

### 5.1 后端（云端）
1. `GET /admin/supplier-notify/pending-dial`（**给本地网关调用**，凭 env 里的共享令牌，不走运营登录）
   → 返回待拨清单：`[{dialId, orderId, supplierId, phone, supplierName, shopName, minutesUnacked, ringSeconds}]`
   → 同一次调用即"派发"：云端立刻把该单记为"已派发（channel=phone）"并计提醒次数，**避免下一分钟重复派**。
2. `POST /admin/supplier-notify/report`（本地网关回报）
   → `{dialId, result: 'dialed'|'connected'|'no_answer'|'failed', durationSec, cause}`
   → 写与现在同一份台账（`SUPPLIER_NOTIFY_CALL`），新增 `channel:'phone'`、`connected:true/false`、`durationSec`。
3. `POST /admin/supplier-notify/gateway-heartbeat`（本地网关每 30 秒一次）
   → 催单台据此显示"手机专线：在线／离线"；**离线超过 3 分钟 ⇒ 列表标"专线离线，请人工跟进"**（不静默失败）。
4. 配置 `supplier_ack_reminder` 增加三个字段（默认值写死，后台可改）：
   - `channel`: `'phone' | 'aliyun' | 'off'`（**默认 phone**，云语音代码保留不用）
   - `ringSeconds`: `5`（**后台可调，范围 1~30 秒，改完即时生效** —— 值随"派发"一起下发给本地网关，不重启、不发版）
   - `hangupAfterAnswerSeconds`: `2`（对方**真接了**之后隔几秒挂断；`0` = 接通立即挂）
   - `gatewayPhoneNo`: 提醒专号（用于后台与供应商端显示、复制）

### 5.2 本地「手机网关」（新增，跑在你的电脑上）
- 一个常驻小程序：每 30 秒拉一次 → 逐个执行「拨号 → 响 N 秒 → 挂断」→ 读 `dumpsys telecom` 判接通 → 回报。
- 已备好的现成件（今天写的）：`C:\Users\Administrator\tools\phonetest\call.sh`（含拨号/挂断/失败重试/台账/截图），网关直接调用它即可，改成输出 JSON。
- 开机自启；手机插在电脑上并开启 USB 调试。

### 5.3 后台催单台（`Reminder.vue`）
- 顶部统计条旁加一个状态：**「手机专线：在线（30 秒前心跳）／离线」**；
- 台账抽屉每行显示：**通道（我的手机／云语音）· 是否接通 · 通话时长**；
- 设置卡加：通道选择、响铃秒数、提醒专号（显示用）。

### 5.4 供应商端
- 「我的」页（📞 电话提醒 开关下面）加一行：**"新订单提醒电话是 XXX，请存为『辉崧鲜配新订单提醒』；本号只作提醒，请勿回拨，有事请拨客服 XXX"** + 一键复制号码；
- 备货单页顶部提示条带上这个号码。

### 5.5 明确**不动**的东西
订单状态机、备货流程、拆单逻辑、其他页面、原有 `@Cron` 判定逻辑、`launchAt` 分界线——一行不改。

## 六、护栏（沿用 5 条 + 新增 3 条）

沿用（都已实现）：上线分界线只打上线后创建的单；只打"待备货+未接单"；无手机号跳过只提醒运营；免打扰时段不补打隔夜单；总开关/上限/供应商自关 + 每通留痕。

新增：
1. **专线离线不静默**：心跳断 → 列表标红转人工；
2. **卡停机/无信号拨测告警**（实测吃过这个亏：卡停着时界面照样显示"正在拨号"，看着像打出去了其实没通）；
3. **号码为空/格式不对 → 跳过并提醒运营**（沿用，但要在页面上显眼）；
4. **同一供应商冷却 `supplierGapMinutes`（默认 10 分钟，后台可调 1~1440）** —— 端到端实测发现的问题：一个供应商名下有多张超时单时，会被**连打多通**（实测 40 秒内 3 通）。修法两条：① 一轮内同一供应商**只取一单**（取最久未处理的那张）；② 该供应商在冷却期内整轮跳过。

## 六之二、端到端联调实测（2026-10-04，三黑 + 小黑 + 专号手机）

拓扑：手机插在**小黑**（.249）→ 小黑上的网关（Node 常驻，`tools/phonetest/gateway.js`）→ 三黑上的后端（`192.168.1.78:3001`，带网关令牌）。

| 环节 | 实测结果 |
|---|---|
| 网关心跳 | `POST heartbeat` 201 / code 0，催单台随即显示「在线（3 秒前心跳）」 |
| 取件 | `GET pending-dial` 返回候选（含明文号码、`ringSeconds`、`hangupAfterAnswerSeconds`） |
| 拨号+挂断 | 小黑驱动 MI 8 拨出 → 响 5 秒 → 挂断，一通 8~9 秒（`no_answer`：机主没接） |
| 台账回写 | 每通两行：`dispatched`（取件时）+ `no_answer`（回报时，带 `durationSec`），`channel=phone`，号码只存脱敏值 |
| **多单连打（修复前）** | 同一供应商 3 张超时单 → **40 秒内连打 3 通**（从日志一眼看出） |
| **修复后复测** | 同一供应商 3 张超时单 → **只打 1 通**（`取到待拨 1 条`）；回报行也带上了 `supplierId`（修前为空） |
| 收尾 | 测试号还原、提醒计数归零、本地 `enabled=false`（不留会自动拨号的配置） |

## 七、前置问题：**已排除**（早前判断看错了库，这里更正）

> ⚠️ 更正：早前说"3 个供应商都没手机号"，那是**本机开发库**（里面只有 3 条测试供应商、phone 全空）。**生产库完全不是这样。**

生产库实测（2026-10-04 直连查询）：

| 项目 | 生产实际 |
|---|---|
| 供应商总数 / 合作中 | **4 家，全部 status = 1** |
| **有手机号** | **4 家全都有**（已逐个核对；其中"测试档口-大辉(勿用)"那个是自测账号） |
| 近 14 天订单 | 49 单 |
| 近 14 天「订单 × 供应商」对数 | 68 对 |
| 当前「待备货 + 未接单」 | 6 对 |

**结论**：
- **不需要"补手机号"的前置工程** —— 供应商端「我的」页只做"存备注"引导即可（见 5.4）。
- 按真实规模，一天最多几通电话 ⇒ 手机专线绰绰有余，也远低于运营商风控线（单日 300 通 / 1 小时 30 通）。
- 「号码为空则跳过」仍保留为**兜底护栏**（新供应商还没填时的正常分支），不再是阻塞项。

## 八、成本（按生产真实规模算）

- 生产近 14 天：「订单 × 供应商」68 对，当前未接单 6 对 ⇒ 即使每单都打满 2 通，**一个月也就百来通**。
- 走专号卡：**0 元/通**（套餐内）+ 号卡月租约 10 元/月。
- 走云语音：0.11 元/接通（未接通不计费）⇒ 一个月十几元；要"固定显号"再加 35 元/月。
- 结论：两条路都便宜到可以忽略；**选手机不是因为省钱，而是因为① 能"只响铃不说话"（云做不到）② 显示的是你自己、供应商能回拨的号**。

## 九、待你拍板（3 条，每条都有默认）

1. **网关跑在哪台电脑**：默认 **小黑（.249，一直开着）**，那台插手机；插本机（三黑）也行，你定。

## 十、这版**不做**（避免误会）

- 不做语音播报 / 不做 AI 通话；
- 不做"供应商接起来还能对话"；
- 不切到云语音通道（代码保留，随时可切）；
- 不做号码自动抓取（必须供应商自己填或运营代录）。
