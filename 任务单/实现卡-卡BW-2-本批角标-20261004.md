## 二、怎么做（口径写死，照做即可）

### 1) 本批标记怎么传（**纯内存，不落库、不写后端、不用 uni storage 也行**）
`utils/batch-session.js` 导出一个模块级 `Set`：

```js
const ids = new Set()
export function markBatch(applyIds) { (applyIds || []).forEach((i) => ids.add(Number(i))) }
export function isBatch(applyId) { return applyId != null && ids.has(Number(applyId)) }
export function clearBatch() { ids.clear() }
```

模块级变量在同一个 App 运行期内跨页面存活 —— `batch-listing` 用 `uni.redirectTo` 回列表页会重建页面实例，但**模块实例不重建**，所以标记拿得到。**不要**写成 storage / 不要落库 / 不要动后端。

### 2) `batch-listing.vue`：提交成功时把 applyId 交出去
- `POST /supplier-goods/apply` 的返回是 **`{ applyId, status:'pending' }`**（后端 `supplier-goods.service.ts:219`）。
- 现在代码里 `await supplierApi.submitGoods(...)` **把返回值丢掉了** → 改成接住，成功一条就把它的 `applyId` 收集起来（`submitOne` 与 `doSubmitAll` 两处都要）。
- 全部提交过程结束后（含「单独提交」），调 `markBatch(收集到的 applyIds)`；重试成功的也要补进去。
- **只有「连拍上架」批次里提交成功的条目才算本批**；老入口「＋ 提交新商品」提交的**不算**（那是单条链路，别去动它）。

### 3) `goods-manage.vue`：列表项加角标 + 行底色
- 在 `v-for="g in goods"` 的列表项上：
  - 行容器加条件类：`:class="{ 'row-batch': isBatch(g.applyId) }"` → CSS `background: #F2FBF7;`
  - 名称旁边加一个小角标：`<view v-if="isBatch(g.applyId)" class="tag-batch">本批</view>` → 浅绿底 `#E6F9F0`、字 `#00995A`、小圆角、字号 11px。
- 引入：`import { isBatch } from '@/utils/batch-session'`。
- **匹配用 `applyId`，不要用名称**（列表项已带 `applyId`，见 `supplier-goods.service.ts:118`）。
- **不许改**：老入口、老表单、老列表的筛选/排序/字段、`load()`、`tapEdit/tapStock/askToggle/askDelete` 等任何既有逻辑。
