## 一、背景与已核对现状（逐行核过，别凭印象改）

| 环节 | 现状 |
|---|---|
| 运营后台 新增/编辑商品<br>`admin-web/src/views/goods/GoodsManage.vue:91` | 「单位」是**自由输入框**，默认「斤」，placeholder 是"斤 / 份 / 箱"；**后台没有任何"单位管理"入口** |
| 供应商端「提交新商品」表单<br>`frontend/src/subpkg-supplier/pages/goods-manage.vue:74-82` | **只有**「计量方式」两个 chip：`称重（斤）` / `固定规格`；**根本没有"单位"这一项** |
| 供应商端同文件的另外两个表单 | 「编辑商品（走变更审核）」「编辑待审商品（卡BQ）」结构同上，也都没有单位项 |
| 后端 `backend/src/modules/supplier-goods/supplier-goods.service.ts:161` | `unit: dto.unit ?? '斤'` —— 供应商没传单位就**写死「斤」** |
| DTO | `apply-goods.dto.ts` / `change-goods.dto.ts` / `edit-pending-apply.dto.ts` 都有可选 `unit` 字段（前端从不传） |
| 买家端显示位 | **已全部读同一个 `unit` 字段**：商品卡 `¥2.5/斤`、商品详情 `¥2.5 /斤` + `今日可售 200 斤`、购物车、订单详情、售后页、AI 语音确认卡、以及供应商端全部单据（`订 10斤`、`实交 8斤`） |
| AI 语音 | `backend/src/modules/ai/parser/parser.util.ts` 有「份数单位 → 斤」的唯一换算口径，**只在 `weighType=1`（称重）生效** |

**一句话结论**：后台输入框能打「瓶」，但 ① 供应商端选不到、② 后端写死「斤」⇒ 粮油类商品提交上来全是「斤」。
**买家端显示链路是通的**，单位值一变，全站自动跟着变，不用逐页改。

## 二、要出的四块画面（同一张原型里，用分栏或页签区分）

### 画面 1：供应商端「提交新商品」表单 —— **最重要**

- 在现有「计量方式」行**下面新增一行「单位」**。
- 单位用**平铺可点标签（chip）**，**照抄同页「商品分类」「计量方式」的 chip 样式**；**禁用下拉菜单、禁用 `<picker>`**。
- 选项来自后台维护的单位表，预置至少：`斤`、`公斤`、`袋`、`桶`、`箱`、`瓶`、`件`、`把`、`个`、`块`、`板`、`盒`、`包`、`罐`、`扎`、`提`、`捆`、`筐`（分行平铺，一行放不下自动换行）。
- 默认选中 `斤`（与现状一致）；点一下即选中，**没有"其他 / 手填"入口**（供应商不允许自己加单位）。
- 要画出**选中「瓶」之后**的样子：供货价 placeholder 由「如 2.20（元/斤，提交后审核）」变「如 120（元/瓶，提交后审核）」；日可供量 placeholder 由「如 200（斤）」变「如 50（瓶）」。
- 「计量方式」那两个 chip 现在写死是 `称重（斤）`——原型里**出两版对照**，让大辉选：
  - A 版：维持 `称重（斤）` / `固定规格`（单位另外选，可能出现"称重 + 瓶"这种组合）
  - B 版：改成 `称重` / `固定规格`（把写死的"斤"去掉，单位一律看下面那行）
- 「编辑商品」「编辑待审商品」两个弹层**也要各出一版**带单位行（与提交表单同一套 chip）。

### 画面 2：运营后台「计量单位」维护页 —— **新增页面**

大辉自己按需要添加单位，所以要一个独立入口（放「商品管理」分组下）：

- 单位列表：`单位名称`（斤 / 瓶 / 桶 …）、`排序`、`状态`（启用 / 停用）、`操作` 四列
- 顶部：**`＋ 新增单位`** 按钮 → 输入名称 → 保存
- 每行操作：`上移 / 下移`（排序，决定供应商端标签顺序）、`停用 / 启用`
- **不提供「删除」**（口径：单位只用过就停用、不真删。停用后：新建商品与供应商端不再出现，**老商品与历史订单照常显示原单位**）
- 重名要拦（已存在同名单位 → 提示"该单位已存在"，不许重复添加）

### 画面 3：运营后台 新增/编辑商品 → 单位栏

- 单位改成**从维护表里选**（后台可以用 `el-select` 下拉），不再自由输入 —— 否则自由输入会造出表外的脏值。
- **兼容细节（必须画到）**：编辑老商品时，如果它当前的单位已被停用，下拉里要**保留该项并标注「（已停用）」**，不许显示成空白。
- 下拉下方灰字提示：「没有想要的单位？到『计量单位』页添加」。

### 画面 4：买家端显示对照（证明"改值即生效"）

- 商品卡：`¥120 /瓶` + 商品名（右上角价格位）
- 商品详情：`¥120 /瓶` + `今日可售 50 瓶`
- 一袋米（单位「袋」、规格「25kg/袋」）的卡片对照

## 三、原型里**不许出现**的做法

1. 不许用下拉菜单 / `<picker>`（**供应商端**单位必须平铺可点；运营后台不在此限，可以用 `el-select`）。
2. 不许在供应商端放"其他（手填）"入口。
3. 不许出现"删除单位"按钮（只有停用 / 启用）。
4. 不许改配色、不许新造视觉语言 —— 一律沿用现有页面既有样式。

## 四、实现方案要点（原型要能把这几点讲清楚；后续实现卡照此写）

1. **单位从哪来**：新建小表 `measure_unit`（`id / name / sort / status(1 启用 0 停用) / createdAt`）+ 接口 `GET /admin/units`、`POST /admin/units`、`PATCH /admin/units/:id`（改名 / 排序 / 启停），以及给供应商端与后台商品表单用的只读 `GET /units`（只返回启用中、按 sort）。
   - **预置一批常用单位作为初始数据**（清单见画面 1）。预置是**新表初始化**，**不动任何现有商品数据**（大辉口径：现有商品不动）。
   - 万一有冷门单位没预置（如老商品用的「颗」），大辉在维护页补一条即可 —— 老商品照常显示，不受影响。
2. **后端**：供应商提交/变更时 `unit` **传什么存什么**，去掉 `?? '斤'` 写死；`unit` 改必填，并校验必须命中**该表启用中的单位**（挡住绕过前端塞脏值）。
3. **供应商端三处表单**都要带上单位：「提交新商品」「编辑商品（变更审核）」「编辑待审商品」。
4. **买家端 + 供应商单据**：**零改动**（已读同一字段）。
5. **AI 语音**：单位出现「斤」以外的值之后，必须冒烟一句「**来五瓶油**」，确认没被算成斤（**验收时做，不在原型里**）。
6. **计量方式不绑定单位**（大辉口径：不新加绑定关系）——「称重 / 固定规格」与「单位」各自选，互不联动。
