### ⑤ C —— 时区（`admin-finance.service.ts`）

**改动 diff**（`NOW(3)` → `UTC_TIMESTAMP(3)`）：

```diff
@@ INSERT INTO service_fee_config (category_id, rate, updated_by, updated_at)
-        VALUES (${categoryId}, ${dto.rate}, ${userId}, NOW(3))
+        VALUES (${categoryId}, ${dto.rate}, ${userId}, UTC_TIMESTAMP(3))
       ON DUPLICATE KEY UPDATE
         rate = ${dto.rate}, updated_by = ${userId},
-        updated_at = NOW(3)
+        updated_at = UTC_TIMESTAMP(3)
```

**改动前 / 改动后同一接口的关键数字**（BEFORE 为上一轮所取，AFTER 本轮复跑，`补卡-C-service-fee-utc-AFTER.log`）：

| | BEFORE（`NOW(3)`） | AFTER（`UTC_TIMESTAMP(3)`） |
|---|---|---|
| `GET /admin/finance/service-fee` | `{"globalRate":0.05,"categories":[]}` | `{"globalRate":0.05,"categories":[]}` |
| `PUT {rate:0.05}` 返回 | `{"rate":0.05,"categoryId":null}` | `{"rate":0.05,"categoryId":null}` |
| 再 GET 一次 | `{"globalRate":0.05,"categories":[]}` | `{"globalRate":0.05,"categories":[]}` |
| 费率是否完全一致 | ✅ 一致 | ✅ 一致 |
| 库里 `updated_at` vs `UTC_TIMESTAMP(3)` | `updated_at=2026-09-25 08:15:41` / `utc_now=00:15:41` → **差 -479 分钟** | `updated_at=2026-09-25 01:20:50` / `utc_now=01:20:50` → **差 0 分钟** |

**说明数字**：费率这条业务口径**从头到尾都是 0.05，没变**（`globalRate=0.05`、PUT 回包 `0.05`、再读仍 `0.05`），
说明这次只动了时间戳写法，没碰业务。变的是那一列时间：改动前写进去的是**本地时间（+08）**，
而 Prisma 读写 `datetime(3)` 按 UTC 解释 → 运营在后台看到的是「8 小时后更新的」；
改动后 `updated_at` 与 `UTC_TIMESTAMP(3)` **完全相等（差 0 分钟）**。
（BEFORE 显示 `-479` 而不是整 `-480`，是 `TIMESTAMPDIFF` 按分钟向下取整造成的 1 分钟内截断，量级仍是 8 小时。）
