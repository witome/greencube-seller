## 四、踩坑记录（本机/本项目专用，避免下次重复）

### 4.1 ⚠️ `agent-browser` 本机不可用（本卡第一轮卡死的原因）
`agent-browser` 首次使用要**自带下载 Chromium**，本机下载走不通，命令会**长时间挂住不返回**
（表现为「正在执行命令」不结束）。**本机浏览器验证一律用 `playwright-cli`**（Chromium 已在
`ms-playwright/chromium-1234` 缓存里，可直接用）。

### 4.2 ⚠️ 后台进程会在**该条 bash 命令结束时被回收**
`nohup ... &` 起的服务活不过命令边界。正确做法：用**后台任务**（Bash 工具 `run_in_background`）
以**前台进程**方式常驻（`node dist/main` 直接跑，不加 `&`），后续命令就能一直复用它。
本卡最终就是：后端(:3001) 与 H5 dev server(:5199) 各一个常驻后台任务 + 每条浏览器命令独立小步。

### 4.3 ⚠️ `VITE_API_BASE` 必须**带 `/api/v1`**
`request.js` 里 `const BASE_URL = ENV_API_BASE || 'http://192.168.1.78:3001/api/v1'` —— 环境变量是**整段 base**，
不是 host。本卡第一次写成 `http://127.0.0.1:3001`，导致 `/auth/wx-login` 打成了
`http://127.0.0.1:3001/auth/wx-login` → **404**，登录拿不到 token，整个 E2E 卡在登录页。
正确写法：`VITE_API_BASE=http://127.0.0.1:3001/api/v1`。

### 4.4 ⚠️ uni-app H5 的 storage 有命名空间，**不能**用裸 `localStorage` 改
用 `localStorage.removeItem('token')` / `setItem('devRole', ...)` 对 `uni.getStorageSync` **不可见**，
会让 App 在重载后按默认 `devRole='buyer'` 重新登录，身份被静默换掉。
必须用 `uni.setStorageSync` / `uni.removeStorageSync`。

### 4.5 ⚠️ 网页跳转尽量走 hash，别整页 `goto`
整页 reload 会触发 `App.vue onLaunch` 的 token 复验（会重新调 `wx-login` 并按 `devRole` 重选身份）。
同 SPA 内跳页用 `location.hash = '#/xxx'` 更稳。

### 4.6 `curl` 的 argv 会破坏中文（沿用上一张卡的结论）
`curl -d '{"reason":"中文"}'` 落库会乱码（Git Bash 按系统码页转换 argv）。
本卡所有中文 body 一律先用 node 落成 **UTF-8 文件**再 `curl -d @<文件>`，且路径用 Windows 形式 +
`MSYS_NO_PATHCONV=1`（否则报 `option -d: error encountered when reading a file`）。
`playwright-cli run-code` 里的中文同理，一律写 `\uXXXX` 转义（脚本保持纯 ASCII）。

### 4.7 ⚠️ 查「小写 action」不能直接 `action <> UPPER(action)`
`audit_log` 表是 `utf8mb4_unicode_ci`（大小写不敏感），该条件**永远为假**，会得出「没有小写 action」的错误结论。
必须做二进制比较：`WHERE CAST(action AS BINARY) <> CAST(UPPER(action) AS BINARY)`
（MySQL 8 里 `REGEXP BINARY` 会报 3995，别用）。
