E6 重放「改前」的并发交错（真表 · 事务内 · 最后回滚，零残留）
========================================================================
  ① 两个并发请求各自的「先查有没有」：0 行 / 0 行 → 都会走 INSERT
  ② 第一个请求 INSERT 成功，此时该分类行数 = 1
  ③ 第二个请求 INSERT 被数据库拒绝（这就是改前会出两条、现在出不来的那条路径）：
      Invalid `prisma.$executeRawUnsafe()` invocation:   Raw query failed. Code: `1062`. Message: `Duplicate entry '999998' for key 'service_fee_config.uk_service_fee_config_global_key'`
  回滚后该分类残留行数 = [
  {
    "c": 0
  }
]  （应为 0）

  ⚠️ 说明：本库的 lvlifang_app 没有 CREATE TEMPORARY TABLES 权限（报 1044），
     无法另建一张「无唯一键」的表来实证「改前会出两条」。
     故「改前会出两条」是**推理结论**（原代码两次 INSERT、且当时表上无任何唯一约束），
     未被实证复现；被实证的是上面这条 —— 同样的交错现在会被库拒绝。
     MySQL 不约束 NULL 的唯一索引语义（本卡要绕开的坑）——只读核对：
     [
  {
    "plain_eq": null,
    "nullsafe_eq": 1
  }
]  ← `=` 对 NULL 得 NULL（永不为真），故 @@unique([categoryId]) 挡不住多条 NULL
