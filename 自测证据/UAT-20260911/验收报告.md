## 7. 追加修复：商品列表「一直显示加载中」（2026-09-11 12:15）

### 现象与根因

大辉反馈「我的商品列表一直显示加载中」。排查结论：

| 排查项 | 结果 |
|---|---|
| 后端 3001 | ✅ 在线 |
| `GET /product/categories`、`GET /product/list` | ✅ HTTP 200 / code 0 / 7 个商品 |
| 本机 IP 是否变化 | ✅ 仍是 `192.168.1.78`，`http://192.168.1.78:3001/...` 返回 200 |
| H5 端直接打开商品列表 | ✅ 正常渲染 7 个商品，**不卡加载中** |

**根因：`goods.vue` 的 `loadGoods()` 没有 try/catch，`loading` 一旦置 `true` 就再不复位。**
只要请求失败过一次（例如后端重启窗口内恰好点进页面、网络抖动、手机与电脑不在同一网段），
页面就**永久停在「加载中」**，网络恢复后不会自愈，也没有任何重试入口，只能整页刷新。

### 复现证据（修复前）

用浏览器把 `/product/list` 请求 abort 一次（等价于后端不可达）：

```
请求失败后页面文本 = 商品列表 … 加载中…      → 卡住 ✅复现
模拟恢复网络，再等 10s                      → 仍卡住、卡片数 0、页面无「重试」入口
手动刷新整页                                → 卡片数 7，恢复正常
```

- 📸 `90-复现-请求失败后卡在加载中.png`
- 📸 `91-复现-网络恢复后仍卡住且无重试.png`

### 修复内容（只改 `frontend/src/pages/buyer/goods.vue` 一个文件）

1. `loadGoods` 改 `try / catch / finally`：**`finally` 里必定复位 `loading`**；失败时给出可见提示
2. 新增失败态 UI：`商品加载失败，请检查网络后重试` + **「点击重试」** 按钮（📸 `92-修复后-加载失败给出重试.png`）
3. `onShow` 里补一次：`if (loadError.value && !loading.value) loadGoods()` ——
   用户切走再切回来会自动重载，不再停在失败态
4. `loadCategories` 也包了 try/catch（分类失败不阻塞商品列表）
5. 上拉加载更多失败时给 toast「加载失败，请稍后重试」，不阻塞后续加载

【场景 3 · 网络恢复后点重试】恢复加载 7 个 ✅ / 失败提示消失 ✅
【场景 4 · 失败后切走再切回】onShow 自动补载成功 7 个 ✅
