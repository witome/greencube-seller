### 1.4 关键实现点

- **归属过滤写进 `where`**：`findFirst({ where: { id, purchaserId } })` → 别人的订单一律 4001，
  不泄露「该订单存在但不属于你」。
- **并发安全**：用条件更新 `updateMany({ where: { id, buyerPaidClaimAt: null } })` 把「判存在 + 写」
  压成一步（与卡J 同思路），并发双声明只有一个真正写入。
- **幂等**：已声明过直接返回既有时间 + `alreadyClaimed: true`，**不报错、不刷新时间、不重复写审计**。
- **审计 action 全大写**：`BUYER_CLAIM_PAID`。全表二进制比对仍只有 `courier_report` 一个小写，**未新增小写**。

### 2.1 一个必须先说的实现判断

`cod-pay.vue` 里**既有的**模拟支付通道（`mockPay`，用于「待确认(10) + 微信支付(1)」那一步）**我没动** ——
它不在本卡范围。本卡新增的两个按钮**完全不碰**它：E2E 已证明点「微信直接支付」不产生任何 `/payment/*` 请求。

### 2.2 配送员端「提示一次」怎么复用的（要求 ④）

**没有新写一套轮询。** 做法是给 `utils/new-order-alerter.js` 加一个**可选的 `onFresh` 回调**（默认仍是播音频）：

```js
useNewOrderAlerter(fetchClaimIds, {
  tag: 'courier-paid-claim',
  onFresh: (ids) => uni.showToast({ title: `${ids.length} 单客户称已付，请核对是否到账`, icon: 'none' }),
})
```

于是 30s 周期、首轮建基线、`pickFreshIds` 去重、权限错误自停、`registerPoller` 全局登记
**全部原样复用**；两条 alerter 共用一次请求（5 秒 TTL 缓存，避免同一次轮询把接口打两遍）。

## 六、遗留 / 建议（本卡不做）

1. **后台展示「客户称已付」**：见 §5，需另开卡动 `admin-web/`。
2. **配送员「跳过收款」后没有回收款页的入口**：`deliver()` 交付后会自动跳收款页，若点了「跳过」，
   「已完成订单」区目前**没有任何按钮**能回到该单的收款页（这是本卡之前就存在的缺口，非本卡引入）。
   本卡只按要求加了标记，没有新增入口——那会动到既有 COD 收款流程的 UI，超出本卡范围。**建议大辉拍板是否补入口。**
3. **已核销后仍可声明**：接口允许「已上传收款凭证」之后再点「我已付款」（不报错、只补一个声明时间）。
   两个状态分开显示，不影响核销口径，但若希望「已核销就不必再声明」，需要一条业务规则，本卡按「不发明规则」处理。
4. **`wx.requestPayment` 仍未接**：「微信直接支付」目前只提示即将开通，等商户号到位后替换弹窗即可，**界面无需重做**。
